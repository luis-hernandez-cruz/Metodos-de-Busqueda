Algoritmos de Búsqueda

La búsqueda es una de las operaciones más importantes en el procesamiento de información. Consiste en localizar un elemento dentro de una lista o conjunto de datos para recuperar información lo más rápido posible.

Clasificación

Según el lugar donde se almacenan los datos:

  • Búsqueda interna: Elementos en la memoria principal (arreglos, listas enlazadas o árboles).
  • Búsqueda externa: Elementos en memoria secundaria (disco duro, cintas, SSD, etc.).

Métodos principales: Secuencial, Binaria, Por transformación de claves (Hash) y Árboles de búsqueda.

Importancia y Complejidad

Permiten optimizar procesos y manejar grandes cantidades de información mediante la notación Big O, midiendo el equilibrio entre velocidad de ejecución y uso de memoria.

Búsqueda Secuencial

Consiste en recorrer el vector, con sus datos no necesariamente ordenados, del principio hacia el final. Si se encuentra el valor buscado se da por finalizada la búsqueda; en caso contrario, tras haber recorrido todo el vector se indica que el elemento no está almacenado.

¿Cuándo usarla?

Es ideal para listas pequeñas, datos sin ordenar o cuando las búsquedas son poco frecuentes, ya que evita el costo de ordenar los datos previamente y no consume memoria adicional.

Ventajas

  • Es muy fácil de implementar.
  • Funciona con datos ordenados y desordenados.
  • Se aplica en arreglos y listas enlazadas.
  • En el mejor caso su complejidad es O(1).

Desventajas

  • Baja eficiencia general.
  • Se vuelve lenta con grandes volúmenes de datos.
  • En caso promedio y peor caso es O(n).

Ejemplo de implementación en C#

static int BusquedaSecuencial(int[] numeros, int buscado) 
{ 
    for (int i = 0; i < numeros.Length; i++) 
    { 
        if (numeros[i] == buscado) 
        { 
            Console.WriteLine($"Número encontrado en la posición {i}"); 
            return i; 
        } 
    } 
    Console.WriteLine("Número no encontrado"); 
    return -1; 
}

Búsqueda Binaria

Consiste en dividir repetidamente a la mitad un arreglo previamente ordenado. Se compara el elemento buscado con el valor central; si son iguales, termina la búsqueda. Si el buscado es menor, se descarta la mitad superior; si es mayor, se descarta la mitad inferior, repitiendo el proceso hasta encontrarlo.

¿Cuándo usarla?

Se utiliza en listas grandes que ya están ordenadas y requieren búsquedas frecuentes. No es recomendable si los datos cambian constantemente, pues mantener el orden en cada inserción resulta costoso.

Ventajas

  • Reduce a la mitad el espacio de búsqueda en cada paso.
  • Muy rápida incluso con grandes volúmenes de datos.
  • Complejidad O(log n) en caso promedio y peor caso.
  • Complejidad O(1) en el mejor caso.

Desventajas

  • Exige que los datos estén previamente ordenados.
  • No es adecuada para listas enlazadas.
  • Mantener el orden en inserciones frecuentes es costoso.
  • Más compleja de implementar que la secuencial.

Ejemplo de implementación en C#

static int BusquedaBinaria(int[] numeros, int buscado) 
{ 
    int inferior = 0; 
    int superior = numeros.Length - 1; 

    while (inferior <= superior) 
    { 
        int medio = inferior + (superior - inferior) / 2; 

        if (numeros[medio] == buscado) 
        { 
            Console.WriteLine($"Número encontrado en la posición {medio}."); 
            return medio; 
        } 
        if (numeros[medio] < buscado) 
            inferior = medio + 1; 
        else 
            superior = medio - 1; 
    } 

    Console.WriteLine("Número no encontrado."); 
    return -1; 
}

Búsqueda por Funciones de HASH

Consiste en aplicar una función hash a la clave del elemento buscado para obtener directamente una dirección (índice) dentro del vector, sin necesidad de que los datos estén ordenados. En caso de colisión, se aplican métodos de resolución para explorar posiciones alternativas.

¿Cuándo usarla?

Ideal cuando se requiere máxima velocidad de acceso mediante claves únicas (como un ID o usuario) en grandes volúmenes de datos. No sirve para buscar rangos de valores (ej. números entre 10 y 50).

Ventajas

  • Acceso casi directo mediante transformación de claves.
  • No requiere que los datos estén ordenados.
  • Extremadamente rápida con una buena función hash.
  • Complejidad O(1) en el mejor caso y promedio.

Desventajas

  • Manejo de colisiones entre claves.
  • Requiere espacio adicional de memoria.
  • Elegir una buena función hash no siempre es sencillo.
  • En el peor caso puede degradarse a O(n).

Ejemplo de implementación en C#


static void BusquedaHash()
{
    Dictionary<int, string> tablaHash = new Dictionary<int, string>();
    tablaHash.Add(101, "Ana");
    tablaHash.Add(205, "Carlos");
    tablaHash.Add(309, "Luis");
    int claveBuscada = 205;
    if (tablaHash.ContainsKey(claveBuscada))
    {
        Console.WriteLine($"Elemento encontrado: {tablaHash[claveBuscada]}");
    }
    else
    {
        Console.WriteLine("Clave no encontrada en la tabla.");
    }
}
